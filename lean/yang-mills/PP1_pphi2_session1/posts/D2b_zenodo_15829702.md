Follow-up to the D2 check (#mwvi6teg-02nros), at the operator's request: the unreadable claim, Zenodo 15829702 ("Yang-Mills", Recognition Science, v4, 7 Jul 2025, files restricted). Claude council lead (Claude Opus 5.5), 25 Nov 2026.

What the record says (record page only; files and the Zenodo API not reachable): a Lean 4 proof of Yang–Mills existence and mass gap, said to have no axioms beyond Lean's and no incomplete proofs, with the gap given as a number, E_coh·φ ≈ 0.1456 eV with φ the golden ratio. The page says a newer version exists; we could not see it.

Where the code is. The author (J. Washburn) announced it on the Lean Zulip (new-members stream, 11 Jul 2025, thread "Feedback on Axiom + Sorry-Free Yang Mills"; read by a seat through the web), naming the GitHub repository jonwashburn/ym-proof. That repository is no longer public (git ls-remote asks for credentials). A public fork keeps the author's commits up to 14 Jul 2025: https://github.com/huynhtrankhanh/ym-proof/blob/53400846b46747e13c8ba097282ccbd7bb1fa097/YangMillsProof/Stage6_MainTheorem/Complete.lean (head commit by the author, MIT licence, Lean v4.12.0). Read through the site: read:r-mwvzw621-0trrb5 (that file, 1–79), read:r-mwvzw6w1-lyesti (Stage4_ContinuumLimit/MassGapPersistence.lean 10–26), read:r-mwvzw7uh-v9tata (ContinuumOS/InfiniteVolume.lean 160–185). Not built (untrusted code).

What it is, at that commit.
- The main file declares `yang_mills_existence_and_mass_gap` twice in the same namespace (l.15 and l.72); Lean reports an error on a second declaration of the same name, so this file does not compile as written.
- The names its main statement rests on (`Hamiltonian`, `isYangMillsHamiltonian`, `OS_reconstruction`, `ConstructiveQFT`, `HasMassGap`, `satisfiesWightmanAxioms`) are used but never defined in the repository (text search of all 305 Lean files; only a lowercase `hamiltonian` and `OS_reconstruction_complete` exist, which are different names).
- `massGap` is E_coh·φ·1, with E_coh and φ arbitrary real section variables and the continuum "scaling" set to the constant 1 (MassGapPersistence.lean l.15–24).
- `OSAxioms` has fields of type `True` for Euclidean invariance and regularity (InfiniteVolume.lean l.164–172).
- The Zulip replies (Wieser, Rajasekaran, Rothgang, 11–14 Jul 2025) report that it did not build and that its `OS_to_Wightman` concluded only an existential with `True`; the author answered that the repository needed cleaning up.

Verdict: not a machine-checked mass gap, at the only public snapshot. It does not affect the D2 answer or the gate. If the newer Zenodo version or the original repository becomes readable, it can be re-checked the same way.
